# 配置（共有サーバーへ置く）

comken を**共有サーバーへ置いて、社内の実際の値に合わせるまで**の手順。
配置したあとは、各プロジェクトが共有サーバーの comken を直接参照する。

> **このリポジトリは公開している。** 社内のサーバー名・組織 URL・社内ライブラリ名は
> 仮の値（`\\server\share` / `example--sandbox` / `example_libs`）で書いてある。
> **書き換えた値を push しないこと。**

---

## 1. 共有サーバーへ置く

**リリース済みのタグだけを checkout する。** ブランチを置くと、そこへコミットした瞬間に
全プロジェクトへ伝播する。

```bat
git clone <URL> \\server\share\tools\comken
pushd \\server\share\tools\comken
git fetch --tags
git tag -l                 :: 出ているタグを確認する
git checkout v0.11.3       :: 上で確認した最新版
popd
```

---

## 2. 社内の実際の値へ書き換える

**書き換えるのは3ファイル。** 下の表の行だけを変える。
**docstring やコード例の中にある仮の値は変えない**（変えると、うっかり push したときに
公開リポジトリへ社内の実名が載る）。

### 2-1. `comken/toolbox/rpa.py` — 社内 RPA 基盤の import 名

**コードは2箇所ある**（`backoffice` と `intranet`）。**冒頭の docstring は変えない**。
エラーメッセージにも同じ名前が出るので、1つのブロックにつき2行ある。

| 変えるもの | いまの値 | 何にするか |
|---|---|---|
| `backoffice` の import | `from example_libs.v0000.rpa import backoffice as entry` | `example_libs.v0000` を実名へ |
| 同じ行のエラー文 | `RpaLibraryNotFoundError("example_libs.v0000.rpa.backoffice", e)` | 同上（エラー文に出る名前） |
| `intranet` の import | `from example_libs.v0000.rpa import intranet as entry` | 同上 |
| 同じ行のエラー文 | `RpaLibraryNotFoundError("example_libs.v0000.rpa.intranet", e)` | 同上 |

**社内ライブラリは import パスにバージョンが入る**（`社内ライブラリ名.vXXXX.rpa`）。
上がるたびに**ここだけ**を直せば、全プロジェクトが追随する（→ 仕様書 4.19）。

### 2-2. `comken/toolbox/salesforce/sites/sandbox.py` — 組織の情報

| 変えるもの | いまの値 | 何にするか |
|---|---|---|
| `DOMAIN_URL` | `DOMAIN_URL = "https://example--sandbox.sandbox.my.salesforce.com"` | My Domain の URL |
| `CREDENTIAL_PREFIX` | `CREDENTIAL_PREFIX = "sandbox"` | 認証情報のキー名の頭（DPAPI に登録した名前） |
| `REPORT_OPPORTUNITIES` | `REPORT_OPPORTUNITIES = "00O000000000001"` | 実際のレポート ID |

**組織を増やすときは、このフォルダにファイルを足して `SITES` に登録する**
（→ `comken/toolbox/salesforce/sites/__init__.py`）。クラス名も組織名に合わせる。

### 2-3. `comken/services/salesforce_downloader/service.py` — 管理表と履歴の場所

| 変えるもの | いまの値 | 何にするか |
|---|---|---|
| `MASTER_PATH` | `MASTER_PATH = Path(r"\\server\share\tools\salesforce\レポート管理表.xlsx")` | 管理表を置く場所 |
| `HISTORY_PATH` | `HISTORY_PATH = Path(r"\\server\share\tools\salesforce\ダウンロード履歴.csv")` | 履歴を置く場所 |

**管理表そのものはまだ無くてよい。** 場所を決めてから
[はじめて使うとき](../salesforce-downloader.md#はじめて使うとき通しの手順) の手順で作る。

### 変えなくてよいもの

次にも仮の値が出てくるが、**docstring やコード例・記入例なので変えない**。

| ファイル | 何のための仮の値か |
|---|---|
| `comken/toolbox/master_table.py` | docstring のコード例 |
| `comken/toolbox/salesforce/client.py` / `report.py` / `sites/__init__.py` | docstring のコード例 |
| `comken/services/salesforce_downloader/master.py` | **雛形に入る記入例**（使う人が消す） |
| `templates/新規プロジェクト/実行.bat` / `認証情報の登録.bat` | **雛形**。`comken init` が実際の場所を埋める |

## 3. 書き換えた値を守る

```bat
git update-index --skip-worktree comken/toolbox/rpa.py
git update-index --skip-worktree comken/toolbox/salesforce/sites/sandbox.py
git update-index --skip-worktree comken/services/salesforce_downloader/service.py
```

手元の書き換えが checkout で消えず、うっかり push することもなくなる。

> **これは「コードが変わらない限り」しか守らない。** comken 側でこのファイルを変えた
> リリースへ切り替えると、checkout が止まる。そのときだけ `--no-skip-worktree` で解除し、
> **新しいコードに社内の値を入れ直してから**、もう一度 `--skip-worktree` を設定する。

---

## 4. 各 PC で使えるようにする

```bat
setup_comken.bat
```

`PYTHONPATH` と `PATH` にこのフォルダが登録され、`comken init` が打てるようになる。
**実行後に新しいターミナルを開くこと**（環境変数は起動時に取り込まれる）。
配って実行してもらうときは、bat の先頭の `COMKEN_ROOT_FIXED` に場所を書いておく
（→ [README「プロジェクトの準備」](../../README.md#プロジェクトの準備)）。

---

## 5. 動くか確かめる

```bat
:: comken を読めるか
python -c "import comken; print(comken.__version__)"

:: Salesforce につながるか（副作用なし）
python -m comken sf check

:: プロジェクトを1つ作ってみる
python -m comken init テスト
```

---

## 配置したあとに効き始めるもの

**公開 API の互換性ポリシー**（→ 仕様書8章）。共有サーバーへ置いて利用プロジェクトが
参照を始めた時点から、名前の変更には旧名の維持と警告が要る。
**破壊的な整理は配置前に済ませておく。**
