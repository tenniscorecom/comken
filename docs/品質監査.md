# 品質監査

最終監査日: 2026-08-13

## 目的

`comken` 全体を定期的に見直すときの確認範囲と、実機がなければ確認できない残存リスクを
一か所に残す。個別 API の仕様は docstring と各機能の文書を正本とし、このノートには
重複して書かない。

## 自動検査

変更時は次をすべて実行する。

```powershell
python -m ruff check .
python -m ruff format --check .
python -m pytest -q
python export_for_chat.py
```

Ruff では通常の不具合候補に加えて循環的複雑度（`C90`）も検査する。複雑度超過を
単に `noqa` で隠さず、入力検証・変換・外部 I/O など、別々に説明できる責務へ分ける。

## 2026-08-13 の監査結果

- 公開 API、例外一覧、Markdown の相対リンク、文書内 Python スニペットはテストで整合性を確認した。
- 全テストは 768 件成功、17 件スキップ。スキップは説明用の省略スニペットと、
  docstring から作る生成文書に対する意図的な部分一致除外だけだった。
- `Any` は COM、Excel セル値、動的な実行入口など型を確定できない境界に限定されていた。
- 認証情報 JSON の取り込み処理と Excel COM の列名転記処理は責務が集中していたため、
  外部仕様を変えず内部ヘルパーへ分割した。
- `SalesforceCredentialRotator.__init__` は依存先と安全設定を明示するため引数が6個ある。
  現時点では設定オブジェクトを新設するより呼び出し側が読みやすいため、公開形を維持する。
- `config._parse_value` は型ごとの優先順位を上から読める小さなパーサーである。
  return 数だけを減らすと判定順が分かりにくくなるため、現状を維持する。

## 実機確認が必要な境界

次はモックテストだけでは完全に保証できない。該当機能を変更したリリースでは、利用環境で
スモークテストを行う。

- Excel / Access / Outlook の COM オブジェクト差異、Office の版差、権限、ファイルロック
- Selenium と EdgeDriver の版差、ポップアップ制御、クライアント証明書、ダウンロード完了判定
- Salesforce 組織ごとの権限、External Client App のレスポンス項目、API 制限
- DPAPI の Windows ユーザー・PC 間の非互換性

実機でしか分からない事情は、発見した時点で対象モジュールの「なぜ」を説明するコメントか、
対応する機能文書へ追記する。秘密値、実在組織名、実在 ID は記録しない。
