# 受け渡し（handoff）

[README（ドキュメントの入口）へ戻る](../README.md)

取得したファイルを、**取る人と使う人のあいだで受け渡す場所**の決め方。

## 何のためにあるか

同じデータを複数のプロジェクトが使うとき、それぞれが取りに行くと次のことが起きる。

- 同じレポートを何度も取りに行く（Salesforce の API 上限を無駄に使う）
- 認証情報の登録先がプロジェクトの数だけ増える
- **1つのプロジェクトで取得が失敗したとき、そこだけが動かない**

取得を1本にまとめ、落としたものを決まった場所へ置く。使う側は置かれたファイルを
読むだけで、取得の手段（Salesforce・ブラウザ・メール添付）を知らない。

```
Salesforce ──→ 受け渡しフォルダ ──→ 配り先（既存の RPA が見ている場所）
               （取得担当が置く）      （配布担当が配る）
                      ↑
                 取得が落ちたら、人がここへ置く
```

## 一番の利点は「手で置けば動く」こと

夜間の取得が失敗しても、**人が同じ場所へ同じ名前で置けば、後続はそのまま動く**。
朝に気づいてから手作業でやり直す範囲が「置くだけ」で済む。

「途中から動かす」ための特別な仕組みは要らない。**ファイルがあるかどうかだけが条件**
なので、取得が成功して置かれたのか、人が手で置いたのかを使う側は区別しない。

```python
from comken.handoff import Handoff

handoff = Handoff(r"\\server\share\受け渡し")

# 使う側: 揃っているか確かめて受け取る
files = handoff.require("案件一覧", "売上")
rows = CsvReader(files["案件一覧"]).read_rows()

# 取得側: すでに置かれているものは取りに行かない（手で置いたものを上書きしない）
if handoff.find("案件一覧") is None:
    ...
```

## 決めごと

### 日付はファイル名に入れる

`案件一覧_20260814.csv` の形に固定する。フォルダを日付で切らない。

前日のファイルが残っていても名前が違うので、**古いデータで黙って動くことがない**。
`FileFinder.today()` や `date_in_name()` と同じ書式なので、既存のファイル検索と混ぜて使える。

名前の組み立ては `Handoff` だけが行う。置く側と受け取る側で作り方がずれると、
「置いたのに見つからない」という原因の分かりにくい失敗になる。

### 足りないものは全部まとめて知らせる

`require()` は1件目で止めず、足りないものを全部集めてから失敗する。
1件ずつ知らせると、置く人は「1つ置いて再実行」をファイルの数だけ繰り返すことになる。

```
エラー: 受け渡しフォルダに 2 件足りません。
  案件一覧_20260814.csv
  売上_20260814.csv
上のファイルを次の場所へ置いてから、もう一度実行してください:
  \\server\share\受け渡し
```

### 配り先が決まっているなら、集約してから配る

既存の RPA が特定の場所・ファイル名を見ている場合、**そこは変えない**。
受け渡しフォルダへ集約したあと、配布担当が管理表のとおりに配る。

| 名前 | レポートURL | 配り先 |
|---|---|---|
| 案件一覧 | `https://.../Report/00O.../view` | `\\server\rpa_a\input\案件.csv` |
| 売上 | `https://.../Report/00O.../view` | `\\server\rpa_b\データ\売上_最新.csv` |

配り先は**ファイル名まで**書く。RPA は固定名で待っていることが多く、配りながら
名前を変える必要があるため。これで「どれがどこへ行くか」が表1つに集まる
（`copy` の bat に散っている状態から、見る場所が1つになる）。

### 増えるものは表で管理する（config.ini に書かない）

レポートは増える。増えるたびにコードや config.ini を直す形にしない。
**1行1レポートの表**（CSV か Excel）にして、行を足すだけで増やせるようにする。

config.ini の対応表は「キー = 値」の1対1なので、名前・URL・配り先・備考のように
**列が増えるもの**には向かない。件数が2桁になると ini は読みにくくもなる。

URL は**画面のアドレスをそのまま貼る**。人が ID の部分だけを抜き出す工程を挟むと、
そこで写し間違いが起きる。ID の取り出しは `report_id_from_url()` が行う。

```python
from comken.salesforce import report_id_from_url

report_id_from_url("https://example.my.salesforce.com/lightning/r/Report/00O5g00000ABCDE/view")
# → "00O5g00000ABCDE"   ID をそのまま渡してもよい
```

Excel で管理したいときは `CsvReader` を `ExcelReader` に変えるだけでよい。
列名が同じなら、あとの処理は変わらない。

### 組織が複数あるときは、URL のドメインで決める

管理表には**複数の組織のレポートが混ざる**。どの組織へつなぐかは URL のドメイン
（My Domain）で決まるので、表に組織を選ぶ列は作らない。

```python
from comken.salesforce.sites import site_for

site_for("https://組織A.../lightning/r/Report/00O.../view")   # → 組織A のクラス
```

人が選ぶ列を作ると、**URL と組織が食い違ったときに別組織へ問い合わせて
「レポートが見つからない」という原因の分かりにくい失敗になる**。URL から決めれば、
表に行を足すだけで新しい組織のレポートも取れる。

組織クラスは `comken/salesforce/sites/` に置き、`SITES` に登録する。
**登録を忘れた組織の URL は `SalesforceSiteNotFoundError` で止まる**（黙って
別組織へつながることはない）。取得側は組織ごとにまとめてから接続するので、
認証は組織につき1回で済み、**1つの組織が落ちても他の組織は続けられる**。

## 取得側で気をつけること

- **すでに置かれているものは取りに行かない。** 落とし直しを省くためだけでなく、
  人が手で置いたファイルを上書きしないため
- **1件失敗しても残りは続ける。** 5本のうち1本が落ちたときに全部落とすと、
  手で用意する手間が5本ぶんになる
- **失敗があれば終了コード 1 を返す。** 途中で続けたぶん、最後に必ず失敗を報せる。
  ログに出すだけで 0 を返すと、RPA 基盤から見て成功と区別が付かない
- **0 行を成功にしない。** 空の CSV を置くと、使う側は「データが無い日」と
  「取得が失敗した日」を区別できない
