## CSV を読む — CsvReader

`CsvReader(path, encoding=Encoding.AUTO, headers=None)`
文字コードは自動判定（UTF-8 → CP932 の順）。ヘッダーがない CSV は `headers=[...]` で列名を付ける。

| メソッド | 何をするか |
|---|---|
| `rows(columns=None)` | 全行を辞書のリストで返す（`columns` で列を絞れる） |
| `first(column)` | ヘッダー名で指定した列の、最初のデータ行の値を返す |
| `cell(ref)` | `A2` のような Excel 風の参照で1セルを返す（ヘッダーも1行目） |
| `find(key_col, value)` | キーに一致する最初の1行を返す（なければ `CsvRowNotFoundError`。`required=False` なら None） |
| `filter(key_col, value)` | キーに一致する行すべてを返す |
| `column(col_name)` | 1列だけをリストで返す |
| `index(key_col)` | `{キーの値: 行}` の辞書を作る（転記の lookup 用。重複があれば `CsvRowDuplicateKeyError`） |
| `group_by(key_col)` | `{キーの値: 行のリスト}` の辞書を作る（同じキーが複数あるデータ用） |

ヘッダーがある CSV は、列の位置が変わっても壊れない `first("列名")` を使う。
ヘッダーがない、または位置で決まっている CSV は `cell("A2")` を使う。

```python
from comken.csv import CsvReader

rows = CsvReader(r"C:\作業\data.csv").rows()          # [{"注文番号": "A001", ...}, ...]
date_text = CsvReader(r"C:\作業\data.csv").first("日付")  # 最初のデータ行の日付
lookup = CsvReader(r"C:\作業\data.csv").index("注文番号")  # 転記用の辞書
```

## CSV を書く — CsvWriter

`CsvWriter(path, fieldnames, encoding=Encoding.UTF8_SIG)`
デフォルトは BOM 付き UTF-8（Excel でダブルクリックしてもそのまま開ける）。

| メソッド | 何をするか |
|---|---|
| `write_rows(rows)` | ヘッダー + 全行を新規書き込み |
| `append_row(row)` / `append_rows(rows)` | 既存ファイルに追記 |

## Excel を読み書きする — ExcelReader / ExcelWriter / Sheet

読み取りだけなら `ExcelReader(path)` を使う。ブックを `read_only=True` で開き、
書き込みメソッドを公開しない。書き込み・書式設定・保存が必要なら `ExcelWriter(path)` を使う。

`ExcelWriter(path)` で開き、`with` 文で使う。Excel 本体は不要（openpyxl）。
**書き込み後は `save()` を忘れない**こと。

| ExcelWriter のメソッド | 何をするか |
|---|---|
| `ExcelWriter.create(path)` | 新規ブックを作る（save() 時にファイルが作られる） |
| `sheet(name)` | シートのラッパー（下の Sheet）を返す |
| `add_sheet(name, index=None)` | シートを追加し、追加した Sheet を返す |
| `rename_sheet(old_name, new_name)` / `delete_sheet(name)` | シート名の変更 / シートの削除 |
| `read_rows(sheet, min_row=2)` | 行データをタプルのリストで返す |
| `read_rows_as_dicts(sheet)` | ヘッダーをキーにした辞書のリストで返す |
| `iter_rows(sheet)` | 1行ずつ返すジェネレータ（数万行のファイル向け） |
| `read_computed_rows(sheet)` | 数式の**計算結果**を読む（必要時のみ COM に自動切替） |
| `run_macro(name)` | VBA マクロ実行（COM に自動切替） |
| `save(path=None)` | 保存（省略で上書き、パス指定で別名） |

`write_cell` と各書式設定メソッドの `col` は、列番号（1始まり）だけでなく
Excel の画面どおり `"A"` / `"AA"` の列記号でも指定できる。

| Sheet のメソッド | 何をするか |
|---|---|
| `s["A1"]` / `s["A1"] = 値` | セル参照で読み書き |
| `write_cell(row, col, value)` | 行・列を指定してセルに書く |
| `write_row(row, values)` / `write_rows(start_row, rows)` | 行単位で書く |
| `append_row(values)` | 最終行の下に追記 |
| `write_table(rows)` | 辞書のリストを「ヘッダー + データ」でまとめて書く |
| `transfer_by_key(key_col, lookup, column_mapping)` | キー突合で転記（XLOOKUP 的転記） |
| `set_fill` / `set_bold` / `set_number_format` / `set_column_width` | 書式設定 |
| `add_table(name, ref)` | 構造化テーブルを追加 |
| `append_to_table(name, rows)` | テーブル末尾へデータを追記し、範囲を自動拡張 |
| `clear_table(name)` / `replace_table(name, rows)` | 見出しを残してデータを全消去 / 洗い替え |
| `s["A1"] = "=SUM(A2:A3)"` | 数式文字列の保存は可能。ただし自動計算・検証されないため、方針として使用を避ける |
| `auto_width()` | 列幅を内容に合わせる（全角対応） |
| `freeze_header()` | ヘッダー行を固定 |
| `last_row` / `is_empty` | 最終行番号 / 空シート判定 |
| `.ws` | 生の openpyxl Worksheet（ここにない操作用） |

大量データは1セルずつ書かず、行なら `write_rows()`、見出し＋データなら
`write_table()`、キー突合で既存ブックへ転記するなら `transfer_by_key()` を使う。

```python
from comken.csv import CsvReader
from comken.excel import ExcelWriter

rows = CsvReader(r"C:\作業\data.csv").rows()

with ExcelWriter.create(r"C:\作業\report.xlsx") as f:   # 新規作成
    s = f.sheet("Sheet1")
    s.write_table(rows)      # CSV の中身をそのまま表に
    s.auto_width()
    s.freeze_header()
    f.save()

with ExcelWriter(r"C:\作業\台帳.xlsx") as f:             # 既存ファイルに転記
    lookup = CsvReader(r"C:\作業\data.csv").index("注文番号")
    f.sheet("T_data").transfer_by_key(
        key_col="Q", lookup=lookup,
        column_mapping={"A": "顧客名", "B": "金額"},
    )
    f.save()
```

## Excel の既存数式の結果・マクロ・パスワード保存 — ExcelComHandler

Excel 本体を起動して操作する（pywin32）。**openpyxl でできることは ExcelReader / ExcelWriter を使い、
こちらは既存数式の計算結果の読み取り・マクロ・パスワード保存が必要なときだけ**使う。

数式は Power Query や人が用意した範囲で計算し、プログラムは値の書き込みと転記に徹する。
openpyxl は数式を計算しないため、既存ブックの計算結果を Python 側で読む場合は
`read_computed_rows()` を使う。

`ExcelComHandler(path, password="")` — パスワード保護されたファイルも開ける。

| メソッド | 何をするか |
|---|---|
| `read_cell` / `write_cell` / `read_rows` / `read_rows_as_dicts` | ExcelWriter と同じ感覚で読み書き（数式は計算結果） |
| `used_last_row(sheet)` | データのある最終行 |
| `count_a(sheet, row)` | 行の空でないセル数（0 なら空行） |
| `transfer_by_key(...)` | キー突合転記（COM 版） |
| `run_macro("Module1.名前")` | VBA マクロ実行 |
| `save()` | **上書き保存**（close() は保存しないので、変更を残すなら必須） |
| `save_as(path, read_pw="", write_pw="", file_format=None)` | 別名保存。読取/書込パスワード設定可。形式は元ファイルと同じ（変換時のみ `FileFormat.CSV` 等を指定） |

```python
from comken.windows import ExcelComHandler

with ExcelComHandler(r"C:\作業\data.xlsm") as h:
    h.run_macro("Module1.UpdateData")
    h.save()                                          # 上書き保存
    h.save_as(r"C:\作業\提出用.xlsm", read_pw="1234")  # パスワード付きで別名保存
```

## Access のマクロ実行・CSV 出力 — AccessDatabase

Access 本体を COM で操作する（pywin32）。数十万件の出力は、Python で全件を読まず
Access 自身に書き出させる `export_csv()` を使う。既定では DB をローカルに一時コピーして開き、
終了時にコピーとロックファイルを削除する。元 DB を更新する場合は `local_copy=False` を指定する。
この場合は元 DB を開く前に、元 DB と同じフォルダの `backup/` へ日時付きバックアップを取り、
既定で7日間保持する。巨大な DB ではネットワーク越しのコピーに時間がかかるため、
`backup_dir` にローカルフォルダを指定できるが、顧客情報がローカルに残る点に注意する。
元 DB と同じ場所なのでサーバー障害や誤削除では控えも一緒に失われ、本格的な世代保全は
サーバー側のバックアップに依存する。OneDrive などでは控えも同期され、容量と帯域を消費する。

```python
from comken.access import AccessDatabase

with AccessDatabase(r"C:\作業\顧客.accdb") as db:
    db.run_macro("日次整形")
    db.export_csv("T_出力", r"C:\作業\顧客.csv")
```

`run_function()` は VBA、`rows()` は1行ずつ Python で処理するとき、
`table_names()` はテーブル・クエリ名の確認に使う。

## ファイルを探す・動かす — comken.utils.files

| 関数・クラス | 何をするか |
|---|---|
| `FileFinder(folder).today(pattern="*.xlsx")` | ファイル名に今日の日付を含むファイルを返す |
| `FileFinder(folder).dated(pattern="*.xlsx")` | 日付入りファイルを日付の新しい順で返す（同じ日付なら更新日時順） |
| `FileFinder(folder).latest(pattern, by=SortBy.NAME)` | 最新ファイルを返す（名前順 / `SortBy.UPDATED` で更新日時順） |
| `date_in_name(name)` | ファイル名に含まれる最初の日付を `date` で返す（なければ `None`） |
| `DateNameBuilder("売上").prefix()` | `20260713_売上.xlsx` のような日付付きファイル名を作る |
| `move_file(src, dst)` / `copy_file(src, dst)` | 移動・コピー（dst がフォルダなら中へ、親フォルダ自動作成、上書き） |
| `local_copy(nas_path)` | NAS のファイルをローカルに一時コピーして使う（with 文で自動削除） |
| `Paths.downloads()` / `Paths.desktop()` | 実際の Downloads / Desktop の場所（OneDrive 移動にも追従） |
| `zip_folder(folder)` / `zip_files(files, dst)` / `unzip(src)` | ZIP 圧縮・展開 |

```python
from comken.utils.files import DateNameBuilder, FileFinder, date_in_name, move_file

src = FileFinder(r"\\nas\share").today(pattern="売上_*.xlsx")  # なければ FileNotFoundError
out = DateNameBuilder("集計結果").prefix()                      # "20260713_集計結果.xlsx"
move_file(src, rf"C:\作業\done\{out}")
file_date = date_in_name("売上_20260729.csv")  # datetime.date(2026, 7, 29)
```

## ブラウザを自動操作する — comken.browser

必ず Page Object Model で書く（画面ごとにクラスを作る）。selenium を直接 import しない。
詳しい使い方は [ブラウザ操作.md](ブラウザ操作.md)、雛形は `examples/sample_login/` にある。

**サイトが1つでも複数でも書き方は同じ**（増やすときは `launch` を1行足すだけ）:

```python
with Browsers() as browsers:
    kintai = browsers.launch("kintai", KintaiOptions)
    keiri = browsers.launch("keiri", KeiriOptions)     # ← 増えるのはこの行だけ
```

**待ち時間に別のことを進めたいときだけ** `start` で先に始めて `wait` で受け取る:

```python
with Browsers() as browsers:
    勤怠 = browsers.start(lambda: KintaiFlow(kintai).fetch(), label="勤怠")
    keiri_rows = KeiriFlow(keiri).fetch()   # 勤怠の読み込み中にこちらが進む
    kintai_data = 勤怠.wait()                # 戻って結果を受け取る
```

| 部品 | 役割 |
|---|---|
| `Browsers` | 複数サイトのブラウザをまとめて起動・終了する入口。`with` の中で使う |
| `BackgroundTask` | `Browsers.start()` が返す取っ手。`wait()` で結果、`is_done` で終了確認 |
| `BrowserSession` | 1サイト分のブラウザ。`Browsers.launch()` が返す。`download_dir.wait()` で完了待ち |
| `BrowserOptions` | HEADLESS・DOWNLOAD_DIR・WAIT_SECONDS 等の設定（src/browser_options.py に置く） |
| `DownloadDir` | ダウンロード先と完了待ちを管理する（通常は `session.download_dir` 経由で使う） |
| `Page` | クリック・入力・待機などを持つ画面クラスの基底 |
| `SitePage` | `BASE_URL` + `go(path)` を持つ、サイト共通の画面クラスの親 |
| `Locator.id("username")` 等 | セレクターをクラス上部の定数にまとめるための入れ物 |

**画面操作は Locator を渡す形に統一されている:**

| したいこと | メソッド |
|---|---|
| クリック・文字入力 | `click(LOC)` / `input(LOC, text)` |
| テキスト・属性の取得 | `text(LOC)` / `texts(LOC)` / `attribute(LOC, "href")` |
| プルダウン選択 | `select_text(LOC, 表示名)` / `select_value` / `select_index` |
| 表示・非表示を待つ | `wait_visible(LOC)` / `wait_invisible(LOC)` |
| 存在確認・件数（待たない） | `has(LOC)` / `count(LOC)` |
| 一覧の各行を処理する | `elements(LOC)` |
| iframe の中を操作する | `with page.frame(LOC):` |
| 別タブの画面を操作する | `with session.popup_tab():` |

そのほか: `alert_accept/dismiss/text`（確認ダイアログ）、`scroll_to` / `scroll_bottom`、
`drag_drop`、`save_screenshot()`（エラー時の証跡）、`element(LOC)` / `js(script)`（最終手段）。

```python
from comken.browser import Locator
from .app_page import AppPage

class LoginPage(AppPage):
    PATH = "/login"
    USERNAME = Locator.id("username")     # セレクターはクラス上部にまとめる
    LOGIN_BTN = Locator.css(".radius")

    def login(self, username: str, password: str) -> "DashboardPage":
        from .dashboard_page import DashboardPage
        self.input(self.USERNAME, username)
        self.click(self.LOGIN_BTN)
        return DashboardPage(self.session)   # 遷移先の画面クラスを返す
```

## Salesforce を読み書きする — Salesforce

1インスタンスが1組織を受け持つ。認証は OAuth 2.0 クライアントクレデンシャルフローで、
**ユーザー名・パスワード・リフレッシュトークンを使わない**。設計の背景は
[Salesforce設計メモ.md](Salesforce設計メモ.md)、JWT への移行準備は
[Salesforce_JWTと鍵配布.md](Salesforce_JWTと鍵配布.md) を参照。

```python
from comken.salesforce import Salesforce

with Salesforce(
    client_id="接続アプリの Consumer Key",
    client_secret="接続アプリの Consumer Secret",
    domain_url="https://your-domain.my.salesforce.com",   # My Domain 必須
    org_name="site_a",                                     # 計測ログでの呼び名
) as sf:
    records = sf.query("SELECT Id, Name FROM Account")     # 行数の上限なし
    rows = sf.report.run("00O000000000001")                # 上限 2000 行
    sf.metrics.log_summary()
```

| メソッド | 何をするか |
|---|---|
| `query(soql)` | SOQL を実行して全件返す（ページ送り自動・**行数の上限なし**） |
| `get(object_name, record_id)` | レコードを1件取得する |
| `insert(object_name, data)` | レコードを作成して Id を返す |
| `update(object_name, record_id, data)` | レコードを更新する |
| `upsert(object_name, external_id_field, data)` | 外部 ID で更新または作成する |
| `delete(object_name, record_id)` | レコードを削除する |
| `request(method, path, body, component)` | ライブラリに無い API を直接叩く |
| `data_path(path)` | バージョン付きのパスを組み立てる（`request` と併用） |

書き込み系（`insert` / `update` / `upsert` / `delete`）は `dry_run` を尊重し、
実行せずに内容をログへ出す。読み取りは通常どおり実行される。

一時的な失敗は自動でやり直す。**401 はトークンを取り直して1回だけ**（2回目の 401 は
設定の問題なのでエラーにする）、**5xx と 429 は待ち時間を伸ばしながら最大3回**。
4xx はやり直しても直らないので即エラーにする。やり直しは理由別に計測へ残る。

### 組織（サイト）ごとのクラス — comken.salesforce.sites

組織は My Domain の URL が違うので、1組織につき1クラスにする。
共通の操作は `Salesforce` が持っているので、**その組織でしか通じないもの**だけを足す。

```python
from comken.salesforce.sites import SITES, SiteA

with SiteA(
    client_id=..., client_secret=..., domain_url=config.SITE_A.DOMAIN_URL
) as sf:
    rows = sf.案件一覧()

# 3組織をまとめて回す
for site_class in SITES:
    with site_class(**認証情報(site_class.CREDENTIAL_PREFIX), domain_url=...) as sf:
        rows = sf.案件一覧()
```

| クラス属性 | 中身 |
|---|---|
| `CREDENTIAL_PREFIX` | 認証情報のキー名の頭（`site_a_client_id` / `site_a_client_secret`） |
| `CONFIG_SECTION` | My Domain の URL を書く config.ini のセクション名 |
| `API_VERSION` | 組織が対応しているバージョン。既定と違うときだけ上書きする |
| `REPORT_*` | その組織のレポート ID（環境で変わらないのでコードに書く） |

計測の組織名は指定しなければクラス名になるので、ログで組織を見分けられる。

> [!warning] サイト名は仮名
> **このリポジトリは公開しているので実際の組織名を書かない。**
> `SiteA` / `SiteB` / `SiteC` は仮名で、配置時に実名へ書き換える
> （`comken/run.py` の `example_libs.v0000` と同じ扱い）。
> 書き換えるのはクラス名・`CREDENTIAL_PREFIX`・`CONFIG_SECTION` の3つ。

### レポート — ReportApi

`sf.report` が持っている。**同期・非同期のどちらも 2000 行が上限**で、
非同期にしても超えられない（非同期の利点はタイムアウトしにくいことだけ）。

| メソッド | 何をするか |
|---|---|
| `run(report_id, filters=None, allow_truncated=False)` | 同期実行して明細行を返す |
| `run_async(report_id, filters=None, allow_truncated=False)` | 非同期実行（重いレポート向け） |

上限で切り捨てられた場合、**既定では `SalesforceReportTruncatedError` で止まる**。
欠けたデータのまま処理が進むのを防ぐため。承知の上で続けるなら
`allow_truncated=True` を渡すと警告ログだけになる。
集計（サマリ・マトリックス）形式は `SalesforceReportFormatError` で弾く。

```python
# 期間で区切って2000行の壁を回避する
rows = sf.report.run(
    "00O000000000001",
    filters=[{"column": "CREATED_DATE", "operator": "greaterThan", "value": "2026-01-01"}],
)
```

### 計測 — ApiMetrics

`sf.metrics` が持っている。API 呼び出しはすべて1か所を通るので、
呼び出し元別の回数・エラー・リトライ・所要時間がまとめて取れる。

| メソッド・属性 | 何をするか |
|---|---|
| `log_summary()` | 集計を INFO ログに出す（実行の最後に1回） |
| `append_csv(path)` | 集計を CSV へ追記する（日ごとの推移が追える） |
| `api_usage` | 組織の 24 時間 API 消費量（`ApiUsage`。Salesforce のヘッダー由来で自前集計より正確） |
| `truncated_reports` | 上限で切り捨てられたレポート ID の一覧 |

`RetryReason` はリトライ理由の定数（`REAUTH` / `SERVER_ERROR` / `RATE_LIMIT`）、
`ComponentStat` は呼び出し元ごとの集計の入れ物。
`sf.auth` は `ClientCredentialsAuth`（トークン取得の担当）で、
JWT ベアラーフローへ移るときはここを差し替える。
`truncated_reports` を日々ためておくと、**どのレポートを SOQL へ移すべきか**が実測で決まる。

## 社内 RPA 基盤から実行する — comken.run

社内ライブラリは import パスにバージョンが入っている（`社内ライブラリ名.vXXXX.rpa`）。
プロジェクトに直接書くと、バージョンが上がるたびに全プロジェクトの import 行を
書き換えることになるため、comken 側で吸収する。**プロジェクト側は書き換え不要**で、
共有サーバー上の comken を差し替えるだけで新しいバージョンに追随する。

```python
from comken.run import backoffice   # イントラネット側は intranet

def main():
    ...   # ここに処理を書く

if __name__ == "__main__":
    backoffice(main, "受注取込")
```

| 関数 | 何をするか |
|---|---|
| `backoffice(main, project_name)` | バックオフィスの RPA として `main` を実行する |
| `intranet(main, project_name)` | イントラネットの RPA として `main` を実行する |

社内ライブラリ側が設定の初期化と時間計測を行い、`main` を呼ぶ。

**このリポジトリは公開しているため、社内ライブラリ名は `example_libs.v0000` という
仮の名前にしてある。** 共有サーバーへ配置するときに、`comken/run.py` の
`backoffice()` / `intranet()` の中にある import 行を実際の名前へ書き換える。
バージョンが上がったときも、直すのはこの2行だけ。

ログの出力先など「毎回書かされる決まり文句」が増えたときは、同じファイルの
`_prepare()` に書けば全プロジェクトに効く。

社内ライブラリの正式版が出てこの仕組みが不要になったときの消し方は、
`comken/run.py` の先頭に書いてある。

## 設定・ログ・dry-run — 共通の土台

```python
import logging

from comken import config, dry_run

logger = logging.getLogger(__name__)
config.FILES.INPUT_FOLDER               # → Path（初回アクセスで config.ini を読む。型は自動変換）

with dry_run():                     # このブロックだけ書き込みをスキップする
    run()
```

| 部品 | 何をするか |
|---|---|
| `config` | `from comken import config` で config.SECTION.KEY を読む。補完スタブ typings/comken/ も自動生成（Pylance 補完）。src/config.py は不要 |
| `logging.getLogger(__name__)` | 現在のモジュール用のロガーを取得する |
| `with dry_run():` | ブロック内の保存・移動・送信を実行せずログだけ出す |
| `with debug():` | ブロック内だけデバッグログを有効化 |
| `is_dry_run()` / `is_debug()` | 現在その実行モードのブロック内かを返す |

CSV の追記は、書き込み前に全行の文字コード変換を検証する。複数の PC から同じ CSV へ
同時に追記する使い方は想定していない。

ログの設定（出力先・フォーマット・レベル）は社内の共通ライブラリ側で行う。
comken と利用プロジェクトは `logging.getLogger(__name__)` を使うだけでよい。

## エラーが出たら

ライブラリ固有の例外は `ComkenError` 基底で、メッセージに対処法が書いてある。
ファイル不在・タイムアウト・標準的な引数検証では、それぞれ `FileNotFoundError`・`TimeoutError`・`ValueError` が送出されることがある。
まとめて受けるなら:

```python
from comken.exceptions import ComkenError

try:
    main()
except ComkenError as e:
    logger.error("処理を中断しました: %s", e)
```

エラー名ごとの対処は [ERRORS.md](../ERRORS.md) を参照。
