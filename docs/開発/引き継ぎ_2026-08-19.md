## 決まっていること（勝手に変えない）

- **`wait.seconds()` / `wait.minutes()` / `wait.until()` の API は変えない。**
  `sleep_seconds()` などへの改名は不要。`class` + `staticmethod` という形式も、
  `wait.seconds(5)` の読みやすさを作っている本体なので触らない
- **`core/files/` の責務分割（archive / atomic / finder / naming / ops）は維持する**
- **`comken/__init__.py` のファサードは増やさない。** 新しい公開 API は
  `comken/core/__init__.py` まで
- **Salesforce のクラス名は `SalesforceBase` のまま。** パッケージ名 `direct` が
  既に「直接実装」を表しており、クラス名を変えると利用プロジェクトの継承が全部壊れる
- **`bat` は CP932 / CRLF で保存する。** UTF-8 で保存すると cmd.exe で日本語が化け、
  `tests/test_batch_files.py` が落ちる
- **例外は増やさない方針。** 組み込み例外（`FileNotFoundError` /
  `NotADirectoryError` など）で意味が合うならそれを使う

## 作業のルール

- **コミットしない。** 差分は作業ツリーに置いたまま残し、人間が `git diff` で
  確認してからコミットする
- **`git add -A` を使わない。** 別セッションが同じリポジトリを触っている前提で、
  自分が変更したファイルだけを明示的にステージする
- **テストが落ちたら、テストのほうを緩めない。** 検査対象から除外するリストを
  作る、アサーションを弱めるといった直し方をしない。落ちた理由を実装側で直すか、
  直せないなら報告して止まる
- **日本語ファイルは UTF-8 で保存する**（`bat` を除く）。
  cp932 で保存すると docstring が壊れ、Python の構文エラーになる。
  **一度壊れた日本語は元に戻せない**
- **ファイルを移動・改名したら、旧パスの文字列を `grep` して残存参照を洗う。**
  過去に `docs/` のコード例が `ImportError` になったまま、
  テストが存在しないモジュール名を検査して**アサーションが無意味に真**に
  なったまま残っていたことがある
